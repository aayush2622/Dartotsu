## What this is

Dartotsu is a Flutter app: a hybrid **AniList / MyAnimeList / Simkl** tracking and media-management
client (a Flutter rewrite of the Kotlin app Dantotsu). It is a *tracking and management tool* —
streaming/reading content comes from third-party extensions loaded at runtime via the
`dartotsu_extension_bridge` plugin, not from this repo.

Targets 5 platforms: Android, iOS, Windows, Linux, macOS. Distributed outside app stores
(GitHub releases, Obtainium), so the app self-updates (`lib/Api/Updater/AppUpdater.dart`).

### State of the rewrite (2026-09-03)

~200 Dart files vs `main`'s ~350. The foundation layers (Preferences, Theme, DI, networking)
got a correctness/consistency pass; then a **pluggable per-service architecture** was built
(`Queries` / `Mutations` / `ServiceAuth`, see below) with a full **AniList read +
list-management slice** on it: onboarding → login → home/anime/manga sections (folding in the
viewer's status lists) → media detail → list editor → search → notifications → settings, all
on live AniList GraphQL. The service read/write surface was split into `main`-style `Queries`
/ `Mutations` part files. On 2026-09-03 the service layer went **data-only**: per-screen
`*ScreenView` classes whose methods return data (section maps, `SearchResults`, `Media`,
`List<Setting>`) — never a widget — plus a `SettingsScreenView` for a service's own settings;
`Screen/Feed/` renders them; each feature screen's components moved into a `Components/`
subfolder.
`flutter analyze` clean; `flutter build linux` + `flutter run -d linux` verified each step. `ExtensionService` has no watch/read
surface yet. MAL and Simkl are built (see their sections). The worktree usually carries large **uncommitted WIP ahead of the committed
branch** — run `git status` first.

### `.env` file

`.env` is a bundled asset (declared in `pubspec.yaml`) — the build fails without it.
On this branch it holds `hash` (used by `AppUpdater` and `Core/Preferences/Encryptor.dart`),
read via `loadEnv(key)` in `lib/Utils/Function.dart`. (On `main` it held `SIMKL_SECRET`; this branch needs no secrets.)

## Architecture

### Entry flow

`lib/main.dart` → `runZonedGuarded` (zone `print` → `Logger`; uncaught errors →
`AnalyticsManager.recordError` + `handleError`/`ErrorScreen`) → `init()`:

1. `PrefManager.init()` — opens the Isar settings instance
2. `Rhttp.init()`
3. **`DI.init()`** — registers every controller in the locator (see below)
4. `Future.wait([Logger.init(), DartotsuExtensionBridge.init(...), initializeDateFormatting(),
   WindowManager.ensureInitialized() on desktop])`, then `MediaKit.ensureInitialized()` +
   system UI overlay style
5. `unawaited(_postInit(args))` — `DeepLink.init()`, `find<AppUpdater>().checkForUpdate()`

Then `runApp(MyApp())`. `MyApp` is a `StatefulWidget` wrapping `DynamicColorBuilder`
(feeds the dynamic `ColorScheme`s into `ThemeController.setDynamicSchemes`) → `Watch` →
`AppRoot` bound to `_theme.light` / `_theme.dark` / `_theme.themeMode` and
`_locale.locale` (no app-remount key — the locale is watched). It also
installs a `Listener` for the mouse back-button and a non-focusable `Focus` node feeding
`appShortcuts`, and wraps with `Dpad.wrap` (D-pad/keyboard TV nav: global
`DpadTraversalPolicy`, `onBack` (via the shared `guardedBack()` — re-entrant back presses
that used to trip `Navigator._debugLocked` are swallowed), a `DpadThemeData` with a restrained
1.03 scale + 2px border focus effect, no glow).
`home:` is gated on `PrefName.hasCompletedOnboarding`.

**D-pad layers** (`Utils/Nav/DpadLayers.dart`) — focus is organised in layers, each a `DpadRegion` with focus memory: the **shell** (the navbar lane, `shellLaneKey`), the **page** (header `DpadRow`, chips/tabs `DpadRow`, every shelf a `DpadRow`, grids a `DpadColumn`) and **overlays** (sheets/dialogs are their own route focus scope). Left/right stay inside a row (`stop` edge), up/down leave it and re-enter the next row at its remembered item. `layerBack()` (mouse back, Esc, system back) pops a route/sheet first, then moves focus from the page to the navbar, and only then lets the system exit. `DpadEnter` (wrapped around every `navigateToPage` page and `showCustomBottomDialog` sheet) puts focus on the first item when the user is navigating by keyboard. Focus looks: Material controls get theme-level states in `ThemeManager.buildAppTheme` (icon buttons a `secondaryContainer` disc, buttons/segments/switches a 2px ring, tiles/chips a tinted background — only while `usingKeyboard`), custom icons use `DpadIcon` / `dpadScaleFocus` (a little bigger), rows and tiles use `DpadTap` (background colour). `Clickable` is focusable too, so never reach for a bare `GestureDetector`. Our `DpadFocusable` wrapper (`Utils/Nav/DpadNav.dart`) turns the package's auto-scroll off and only reveals the focused item while `usingKeyboard`: Flutter hands focus back to the last focused node when the app regains window focus, which used to scroll Home back to the top.

**TV / keyboard navigation** — `Dpad.wrap` handles arrow-key directional focus + `onBack`
app-wide. Standard Material widgets participate automatically; custom tap targets are wrapped
in `DpadFocusable` (`onSelect`, auto-scroll-to-focus, focus effects): `MediaSection` cards,
`Navbar` items, `HomeHeader` avatar, `SearchScreen` result cards, `DetailScreen` synopsis,
onboarding buttons. `AppDropdown` uses `requestFocusOnTap: true` for keyboard open.

### State management — `Core/State` (our own engine)

Reactivity and DI are home-grown and live entirely in **`lib/Core/State/`**; app code imports only
`State.dart`. GetX is not used by the app any more — `GetBridge.dart` is the one file that touches it, because
the extension bridge package still exposes GetX observables and registers its managers in GetX.

- **`Live<T>`** (+ `LiveList<T>`, `LiveMap<K,V>`; build with `x.live`, `list.liveList`, `map.liveMap`) — the one
  reactive value type, on the `Reactive` mixin (listener list + dependency tracking; a value only allocates a
  `Stream` if someone asks for `.stream`). `pref.rx` is a `Live<T>` too. `onChange(live, cb)` /
  `onAnyChange([...], cb)` / `onFirstChange` return a `Disposer`. `Trigger` (`fire()` / `track()`) re-runs
  watchers after mutating non-reactive data (models, plain sets).
- **`Watch(() => widget)`** — records every `Reactive` read while its builder runs, subscribes to exactly those
  (diffing the set each build, so dropped dependencies are unsubscribed) and rebuilds on change; a change that
  lands mid-frame is deferred to the next frame. It also tracks GetX observables read inside (extension-bridge
  values such as `ExtensionManager.installed`). Reads made later, inside lazy callbacks (`itemBuilder`,
  `LayoutBuilder`, …) are not tracked: read the value into a local first. `BaseScreen` wraps `buildContent` in a
  `Watch`, so a screen only needs `Live` fields.
- **`AppController`** — base class for long-lived controllers: `onInit` once when the locator builds it,
  `onClose` on `delete`.
- **`find<T>()` / `put` / `lazyPut` / `tryFind` / `getOrPut` / `getOrLazyPut` / `delete` / `isRegistered`**
  (`Locator.dart`) — a type-keyed registry (optional `tag`, `permanent`, `fenix`); nothing is ever auto-deleted.
  A type it doesn't know falls back to the GetX registry (bridge managers).
- **`appContext` / `appOverlayContext` / `appNavigator` / `AppRoot`** (`Host.dart`) — the root `MaterialApp`
  owns the navigator key behind the context-free accessors; the locale is just a watched `Live` read by `AppRoot`.

**`StateLog`** prints `[STATE] Instance "X" has been created / initialized`, `"X" onClose() called` and `"X" deleted from memory` in debug builds (`StateLog.enabled`); set `StateLog.verbose = true` to also see every `Watch` rebuild.

**No `setState`**: a `State` keeps its mutable fields as `Live`s and builds under a `Watch` (a plain `State`
renames `build` to `_build` and returns `Watch(() => _build(context))`). `ValueNotifier`s are not used either.

**`lib/DI.dart`** is the single registration point — `DI.init()` in `init()`:

| Controller | Registration | Notes |
|---|---|---|
| `NetworkManager` | `put` (eager) | rhttp client; owns `CookieManager` |
| `AnalyticsManager` | `put` (eager) | Firebase Crashlytics |
| `NotificationManager` | `put(permanent)` + `unawaited(.initialize())` | |
| `ThemeController` | `lazyPut` | reactive theme state (no locale) |
| `LocaleController` | `lazyPut` | `PrefName.appLocale.rx`, watched by `AppRoot` |
| `MediaServiceController` | `lazyPut` | current service + list of services |
| `RefreshController` | `lazyPut` | pub/sub refresh flags (`getOrPut(key)` → `RxBool`, `.all()`); mutations signal it, screens `ever()`-subscribe. `routeObserver` (same file) is on `GetMaterialApp.navigatorObservers` |
| `AppUpdater` | `lazyPut` | AppController; GitHub-release update check + APK / desktop self-update. One `UpdatePhase` (`idle` / `preparing` / `downloading` / `installing` / `failed`) drives `Screen/Update/UpdateSheet` (changelog, progress with size and speed, Cancel, error + Try again); `start()` ignores a second tap while `busy` and only one sheet opens at a time |
| `BaseDiscordRPC` | `lazyPut` | `MobileRPC` on Android/iOS, else `DesktopRPC` |

Local reactive UI uses `Live` + `Watch`; `appContext` / `appOverlayContext` give context-free access
(`getString`, snackbars).

### Theme + `BaseScreen`

- **`Core/ThemeManager/AppTheme.dart`** — `enum AppTheme` is the **single** palette registry
  (`purple` … `ocean`); `themeFor(brightness)` maps to the hand-authored `Themes/*.dart`
  `ColorScheme`s. The theme picker and resolver both iterate `AppTheme.values`.
- **`Core/ThemeManager/ThemeMode.dart`** — `enum ThemeModePref { system, light, dark }`
  (import-free so the prefs layer can reference it).
- **`Core/ThemeManager/ThemeController.dart`** — state only. Every field is a shared
  auto-persisting `PrefName.x.rx` (`useGlassMode`, `isOled`, `themeName`, `useMaterialYou`,
  `useCustomColor`, `customColor`, `cardSize`, `mode`). `light` / `dark` are **memoized**
  `ThemeData` getters (rebuilt only when an input in the cache-key tuple changes; reading the
  tuple keeps them reactive inside `Watch`). `themeMode` / `isDarkModeActive` derive from `mode`.
  Guarded combo setters (`setTheme`, `setOled`, `setMaterialYou`, …).
- **`Core/ThemeManager/ThemeManager.dart`** — pure builders: `buildAppTheme(base, {isOled,
  glass})` applies the (colour-independent, built-once) Manrope `TextTheme` plus the
  **M3-expressive component themes** — pill buttons (`StadiumBorder`, 48px min), rounded icon
  buttons, 20px FAB, connected `SegmentedButton` group on `secondaryContainer`, stadium chips,
  28px cards/dialogs/sheets, 16px menus/inputs/snackbars, filled inputs, `InkRipple`, and the
  updated (`year2023:false`) slider + progress indicator — then switch theme, OLED overrides
  and predictive-back transitions. **`glass`** makes the scaffold + app bars
  transparent and card/dialog/sheet surfaces translucent, so the blurred `GlassBackground`
  shows through the whole stack (not just cards); it's in `ThemeController`'s memo key so a
  glass toggle is a normal `AnimatedTheme` lerp. In glass every tonal role (`primary/secondary/tertiary/errorContainer`, the `surfaceContainer*` layers) is translucent, and the one glass edge (`GlassTheme` extension, `GlassTheme.edgeOf(context)`, a white hairline) is applied to chips, filled/elevated buttons, inputs and `ConnectedPair`, so bars, pills and buttons read as the same glass as `GlassSurface` cards. `deriveCardColor`. Barrel-exports `AppTheme`,
  `ThemeMode`, `Themes/DynamicThemes.dart` (`getCustom*Theme` seed themes, `getImage*Theme`),
  `Themes/material.dart`.
- **`Widgets/Components/ThemedContainer.dart`** — `ThemedContainer` / `ThemedWidget` are real
  `StatelessWidget`s (`ThemedContainer` tells glass mode from the `GlassTheme` theme extension, so it has no `Watch` of its own) — glass-mode-aware card surfaces: in glass mode they render a
  `GlassSurface` (`Widgets/Components/GlassSurface.dart`: one `DecoratedBox` (a two-stop tinted gradient with a faint top sheen and a 1px white hairline — no custom painters or shaders per card, so lists stay cheap on low-end phones) and, only when `blur` is true, a live `BackdropFilter` (`GlassBlur`, one plain Gaussian blur, sigma 14, grouped under `BaseScreen`'s `BackdropGroup`) plus a soft outer shadow). `blur` defaults to **false**: everything that sits in a list or on the page (`SectionCard`, `ShelfFrame`, `PosterCard`, settings rows, tiles, tabs, search fields) is a cheap tinted surface on the already-blurred `GlassBackground`; only floating surfaces opt in with `blur: true` (nav bar, collapsed app bar, `AppSheet` / `CustomBottomDialog` / the font and layout sheets, `AlertDialogBuilder`, the snackbar). Never add `blur: true` to something that scrolls in a list. High-contrast accessibility turns the blur off and the tint near-opaque. `themeDropdown()` lives here too.
- **`Widgets/Components/BaseScreen.dart`** — `abstract class BaseScreen<T> extends State<T>`.
  Implement `buildContent(context)` instead of `build`. Provides `SafeArea` + `Scaffold` and,
  in glass mode, a `GlassBackground` (`BlurredImage`: the image is decoded natively at 160 px on its short side, Gaussian-blurred and saturated once on the CPU in an isolate, returned as raw RGBA, decoded once into a `ui.Image`, cached in an LRU and drawn stretched — no GPU blur, which looked blocky under Impeller's downsampling — inside a `RepaintBoundary` under a surface scrim) behind the content (`buildContent` is built once
  and reused across glass toggles). `glassBackgroundUrl` getter is overridable
  (default `kFallbackGlassBackground`).

### `MediaService` abstraction

**A new service is one subclass with zero core edits.** `MediaService`
(`Core/Services/MediaService.dart`) is **data-only** — every getter returns data or config,
**never a widget**. Anything `null` makes that screen fall back to `NotImplemented(service,
area)`.

| Getter | Type | Purpose |
|---|---|---|
| `getQueries` | `Queries?` | raw fetch layer: `getUserData()`, `getMedia(id)`, `mediaDetails(m)`, `initHomePage()`, `getAnimeList()`, `getMangaList()`, `getMediaLists({anime,userId?})`, `getCalendarData()`, `getGenresAndTags()`, `getBannerImages()`, `getNotifications({page})`, `search(SearchResults?)` |
| `getMutations` | `Mutations?` | `editList(Media,{customList})` / `deleteFromList(Media)` / `setProgress(Media,progress)` |
| `auth` | `ServiceAuth?` | `user` (`Rxn<ServiceUser>`), `isLoggedIn`, `login()` / `loginWithToken(t)` / `logout()` / `refreshUser()` |
| `feedTypes` / `feedView` / `homeView` / `searchView` / `detailView` / `notificationView` / `settingsView` | `List<MediaType>` / `*ScreenView?` | **per-screen data views** (`Core/Services/Screens/ServiceScreens.dart`) — one abstract class per screen, grouping the `Queries` its screen needs + screen config, all returning **data, never widgets**. `feedTypes` declares the browse tabs; one `FeedScreenView` serves them all, every method parameterised by `MediaType` (`userLists(type)` / `browse(type)` / `loadMore(type, section, page)` per-section pagination / `chips(type)` / `shortcuts(type)`). `searchView.types` + `filters(type)` → `SearchFilterSpec` (filter vocab). `settingsView.build(context)` → `List<Setting>` folded into the Account category. - **`Api/Services/Anilist/AnilistViews.dart`** — the AniList `*ScreenView` impls, each

### AniList service (the one wired backend)

**`lib/Api/Services/Anilist/`**:

- `AnilistClient` — GraphQL POST to `graphql.anilist.co` via `NetworkManager`; rate-limit
  aware; `String Function()` token provider. Injected into `AnilistQueries`/`AnilistMutations`.
  `query()` returns the decoded `data` node (light queries + mutations); `queryRaw()` returns
  the response **string** with no main-thread decode — the big list queries
  (`initHomePage` / `getAnimeList` / `getMangaList` / `getMediaLists` / `getCalendarData` /
  `mediaDetails`) run `compute(_parseX, rawBody)` so `jsonDecode` + map→`Media` + sort are all
  off the UI thread. `anilistData(body)` is the top-level envelope decoder used inside the
  isolate.
- `AnilistAuth implements ServiceAuth` (`AppController`, `lazyPut`) — `token` =
  `PrefName.anilistToken.rx`, `user` = `Rxn<ServiceUser>` holding an `AnilistUser`
  (cached to prefs). `login()` runs the implicit grant through `browserAuthenticate` (`client_id 14959`,
  redirect `dantotsu://anilist` on mobile, the loopback `localhost:43721/anilist` on desktop); owns `AnilistQueries queries` + `AnilistMutations mutations`.
- `AnilistQueries extends Queries` — main file + `part 'AnilistQueries/GetX.dart'` files
  (`GetUserData`, `GetHomePageData`, `GetAnimeMangaListData`, `GetMediaDetails`, `GetMediaData`,
  `GetCalendarData`, `GetGenresAndTags`, `GetBannerImages`, `GetUserMediaList`,
  `GetNotifications`, `Search`), each an `extension on AnilistQueries` — GraphQL strings ported
  from `main`'s `AnilistQueries`, map-parsed via the `AnilistMedia.dart` mappers (no
  TypeFactory / generated response models). `AnilistMutations extends Mutations` — parts
  `EditList` / `SetProgress` / `DeleteFromList`.
- `AnilistMedia extends Media` (`AnilistMedia.dart`) — the AniList-only extras (`idMal`,
  `inCustomListsOf`, `userFavOrder`); `anilistMediaFragment` / `anilistAuthorRoles` +
  `mapAnilistMedia` / `mapAnilistListEntry` / `mapAnilistDetail`. `AnilistUser implements
  ServiceUser`.
- `AnilistService` — `getQueries` / `getMutations` / `auth` all just return
  `find<AnilistAuth>()`'s members. No screen code (feed composition lives in `Screen/Feed/`).

### MyAnimeList service (`lib/Api/Services/MyAnimeList/`)

Uses the official MAL API and Tenrai (`api.tenrai.org/v1`, a Jikan-compatible MAL data API, no auth) together. `MalClient` (`api.myanimelist.net/v2`, bearer token or `X-MAL-CLIENT-ID` when logged out) serves login, the user's lists, media details with `my_list_status` and list writes (`MalMutations`, form-encoded PUT/DELETE). `TenraiClient` (3 requests in flight, ~150 ms apart — more than ~5 at once gets 429 — 10-minute LRU GET cache, identical in-flight requests shared, retries on 429/5xx honouring `Retry-After`; `limit` max 50) serves everything public: browse sections (`malSections`), search with filters, schedules (calendar), characters and reviews. `MalAuth` is OAuth with plain PKCE through `browserAuthenticate` (redirect `dartotsu://mal`, client id shared with `main`), refreshes the token on 401. Media ids are `anime/<id>` / `manga/<id>` because MAL ids collide between the two (`parseMalMediaId`); scores are stored 0–100 like AniList and shown with `ScoreFormat.point10`; statuses are mapped to the AniList names (`CURRENT`, `PLANNING`, …). `CalendarEntry.episode` is null for MAL (Tenrai has no episode numbers; it has no user endpoints either, so chapters read are summed from the MAL manga list). The user's lists are loaded once per type into a `LibraryCache` (`Core/Services/Api/LibraryCache.dart`: TTL, shared in-flight load, `expire()` after writes) that feeds home rows, the list screens and the chapter count; the detail page paints the MAL core first, then characters, reviews and staff as Tenrai answers.

### Simkl service (`lib/Api/Services/Simkl/`)

Movies, TV and anime (`feedTypes` = anime / movie — two tabs around Home, the second one labelled "Movies & Series" through `MediaService.feedLabel` and showing both movie and TV trending rows; media ids `anime/<simklId>`, `movies/<id>`, `tv/<id>`). `SimklClient` sends `client_id`, `app-name`, `app-version` and a `User-Agent` on every call and **leaves `Authorization` off the cached catalog and data-file calls** (Simkl asks for that). Browse rows come from the public trending files on `data.simkl.in` (section titles stay plain; the Simkl name and link live on the detail page — see `simklSections`), the calendar from the v2 calendar files, details from `/anime|tv|movies/{id}?extended=full`; the user's library is a `LibraryCache` synced the way Simkl asks: `/sync/activities` always comes first (15-minute TTL), a full sync (`/sync/all-items/shows`, `/movies` and `/anime` one after another) runs only when there is no stored `all` stamp (first sign-in, or after logout), otherwise nothing is fetched while the stamp is unchanged and `/sync/all-items?date_from=<stored all>` fetches the delta; when a `removed_from_list` stamp moves, `/sync/all-items?extended=simkl_ids_only` is diffed against the cache and the missing items are dropped (the Settings *Refresh* button only expires the cache, so it takes this same path); V2 apps have a per-user daily quota (500 requests for a free account) and 1 POST/second, so `SimklClient` queues POSTs 1.1 s apart, retries 429/5xx with backoff, and `SimklMutations.editList` folds episodes + status + rating into one `/sync/history` call. The big calendar files are decoded in an isolate. Writes: `sync/history` (anime episodes with `status`/`rating` in the same entry), `add-to-list` (status only), `sync/ratings` (1–10), `history/remove`. TV shows have a progress field in the editor too: Simkl keeps per-episode history, so `SimklMutations.editList` counts the show's regular episodes in order (`/tv/episodes/{id}`, `parseSimklTvEpisodes`: type `episode`, season > 0) and sends/removes just the episodes between the old and new count as `shows[].seasons[].episodes[]` (`simklShowEpisodes`), then status and rating separately. `MediaService.seriesProgress` (true for Simkl) makes the Watch tab number a seasoned source list absolutely (`seasonOffsets`: Season 2 episode 1 is unit 14 when season 1 has 13), so marking an episode watched writes the right count. `DetailScreenView.sourceName` ('Simkl') turns the detail menu's "Open in browser" into "View on Simkl", which Simkl's API rules require (link to the item's own page); the detail page also ends with a "Data and artwork provided by Simkl" card.

`SimklAuth` uses **AUTH V2 only** (OAuth 2.0 + PKCE S256, scopes `media:read media:write`, 7-day access tokens renewed with the refresh token; V2 apps are public clients, so there is no secret). The client id (public, a V2 "Mobile, desktop & browser app" registered at simkl.com/settings/developer) and the redirect URL `dartotsu://simkl` are constants in `Auth.dart`; the redirect must match the registration exactly. The anime tab has eight rows (three trending files plus rows derived locally from the `*_500` trending files: airing, top rated, movies, ONA, popular — `SimklSection` filter + sort) and your library status/progress is laid over every feed row from the cached library. ### Kitsu service (`lib/Api/Services/Kitsu/`)

### MangaBaka service (`lib/Api/Services/MangaBaka/`)

Manga, manhwa, manhua, novels and OEL (`feedTypes` = manga / novel; the manga tab's chips split manga, manhwa and manhua; section order and visibility are two prefs, `MangaBakaPref.mangaLayout` and `novelLayout`, each with its own Settings row) on `api.mangabaka.org/v1`. `MangaBakaClient` is bearer-token JSON; **`/series/search` is limited to 30 uncached requests a minute** (everything else 180), so search calls go through a one-at-a-time gate that waits ~2.1 s after a Cloudflare MISS (a HIT costs nothing), identical requests are shared and cached 5–10 minutes, 429 retries honour `Retry-After`, and a 401/403 refreshes the token. ### MangaUpdates service (`lib/Api/Services/MangaUpdates/`)

Manga, manhwa, manhua, OEL and novels (`feedTypes` = manga / novel) on `api.mangaupdates.com/v1`. ### Anime-Planet service (`lib/Api/Services/AnimePlanet/`)

Anime and manga (`feedTypes` = anime / manga), list writes go through the site's own XHR endpoints: Anime-Planet has no API, so everything is scraped from the server-rendered pages with a browser User-Agent (`AnimePlanetClient`: one request at a time ~250 ms apart, 10-minute LRU, retries 429/5xx; a 403 means a Cloudflare check). Media ids are `anime/<slug>` / `manga/<slug>` and double as the URL path. `Data/Parser.dart` is pure: `parseAnimePlanetCards` reads the card grids (the tooltip in each card's `title` attribute carries type, studio, years, rating, synopsis and tags), `parseAnimePlanetDetail` reads JSON-LD plus the entry bar, synopsis, tags, `CharacterCard`s (cast and staff), `RelatedEntry`s and the recommendation cards, `parseAnimePlanetFacets` the filter vocab (type and tag ids). Rating is 0–5, stored ×20 as 0–100. Browse rows and search are `/anime|manga/all` with `sort` (`average`, `status_1` most watched, `status_2` most watching, `recent`, `year`, `title`) + `order`, `name`, `include_tags` / `exclude_tags` / `include_types` (comma-separated ids from the facets, cached under `animeplanet_facets/<kind>`), `year` / `to_year`, `season=fall-2026` and `page`; the seasonal row is `/anime/seasons/<season>-<year>` (one page). **Login** (`Auth.dart`): the site's own `PUT /api/login` needs a Cloudflare Turnstile token (`_token`), so `AnimePlanetAuth.login()` opens the in-app `WebView` on `/login` and, once it is closed, reads the session from the cookies the web view already mirrors into `CookieManager`; being signed in is `AP_VARS.USER_NAME` on the home page (`parseAnimePlanetUser`), stored in `AnimePlanetPref.username`; logout clears the domain's cookies. **Lists**: `/users/<name>/anime|manga?page=N` (35 a page; `per_page` is rejected) are parsed by `parseAnimePlanetList` (status from the `statusN` class: 1 watched, 2 watching, 3 dropped, 4 want to, 5 stalled, 6 won't → the Anime-Planet-only status `WONT`, which the list editor offers (`Screens/ListEditor.dart`), the media lists show as its own tab and sync skips; progress from `N/M eps|chs`, a volumes-only count is ignored; score from `ttRating` 0–5, halves, ×20) into two `LibraryCache`s that feed Home rows, the list screen and the state shown on cards. The index files were renamed (`anime-ids-2.json`, `manga-ids-3.json`) because the row layout gained a column, so they download again once. **Entity pages** (`Screens/Entity.dart`, `AnimePlanetEntityView`): characters `/characters/<slug>` (facts from the entry bar and `EntryMetadata`, tags, anime / manga role tables, voice actors from the `tableActors` links), people `/people/<slug>` (details, intro text, one media section per `h3`: Known for, Director, …) and studios `/anime/studios/<slug>` (the title list is a normal card grid, paged with `page`); ids are the slugs (`Character.id`, `Author.id`, `Studio.id`). **Reviews** come from `/<kind>/<slug>/reviews` (`section[itemprop=review]`: author, 0–10 overall ×10, text) through the shared `ReviewsShelf`. **Custom lists** (`/users/<name>/lists` → `parseAnimePlanetCustomLists`: `#customLists .cardHand` with title, path and a kind word, then each `/users/<name>/lists/<slug>` → `parseAnimePlanetCustomList`: the `#customlistDetails` table rows, paged) are loaded by `AnimePlanetQueries.customLists` (two `LibraryCache`s, 10 min, at most 40 lists) and appended after *All* in `getMediaLists`, so every list is a tab of the media lists screen (anime lists on the anime screen, manga lists on the manga one; characters / people lists are ignored). ### List sync (`lib/Screen/Settings/Sync/Data/`, Settings › Account › Sync lists)

Mirrors one service's list (the **main** one, any signed-in service) onto the others. A service opts in with `MediaService.syncAdapter` (`SyncAdapter`, one `Sync.dart` per service): `library(anime:)` returns `SyncItem`s (normalised status/progress/score 0–100 plus every foreign id the service knows — AniList `idMal`, Kitsu `media.mappings`, MangaBaka `source`), `targetId(native)` builds the service's `Media.id`, `write(batch)` is a **throwing** write that returns how many requests it used (AniList stacks `SaveMediaListEntry` aliases 10 per request, Simkl folds a batch into one `sync/history` + `add-to-list` per status + `ratings` + `history/remove`; MAL/Kitsu/MangaBaka go through `Mutations.saveEntry`, the throwing twin of `editList` whose `exists` flag skips lookups and leaves untouched fields alone), `limits` is the request budget (`SyncLimit(requests, per)`, several allowed — Simkl is 50/min and 450/day). Ids are bridged by the shared `IdMapper` (see Id mapper below). `planWith` (pure) pairs each main item with the target's entry: synced / outdated / missing / unmapped, and with *Keep further progress* a target that is ahead stays synced. `SyncController` (`lazyPut`, `startAuto()` in `_postInit`) runs Fetch (one library query per service and type, in parallel, progress bar) and Sync all (one worker per target, concurrent; waits out the budget using request timestamps persisted in `PrefLocation.CACHE`, honours `SyncRateLimited(retryAfter)`, stops on `SyncFatal` such as a 401, retries a failed batch item by item, **Stop** at any time). The whole plan — per-pair state, done/failed — is persisted (debounced) so a restart resumes where it stopped. Modelled on MAL-Sync's list sync (master/slave mirror keyed by MAL id, diff of score/progress/status/dates/rewatch count, add-missing): `SyncPair.diffs` also tracks start/finish dates and repeat count when both adapters declare `syncsDates`/`syncsRepeat` (Simkl does neither), a Completed main entry writes the *target's* own total, and `Media.malId` (Simkl `ids.mal`) supplements the Fribb file. Missing targets whose own id isn't known (manga, anime Fribb lacks) are `missing` with a null `targetId` and get resolved at sync time through `SyncAdapter.resolve` (MAL id → native id: Kitsu `/mappings`, MangaBaka `/source/my-anime-list`, AniList `idMal_in`, Simkl `/search/id?mal=`), as MAL-Sync does. *Sync changes instantly* (`PrefName.syncOnEdit`, in the Sync screen's options, not in the list editor; turning *Auto sync* on implies it, `SyncController.instant`): after a list-editor save, and after every online progress update (`OfflineMutations.onProgressSaved`, set by `SyncController.startAuto`), `SyncController.pushEdit` writes the entry to every other signed-in service (ids from `SyncAdapter.idsOf` + Fribb/resolve, within each service's budget). Auto sync (`PrefName.syncAuto`) fetches and syncs both types 45 s after launch and every 30 minutes; it reads only the main list first and skips the target queries when a fingerprint of it (`syncFingerprint`) is unchanged, nothing is pending and the last full fetch is under 6 h old. The request budget is the pure `SyncBudget` (timestamps per service, `hold` backs off 30 s doubling to 15 min on repeated `SyncRateLimited`, honouring a longer `Retry-After`); `SyncMemory` (persisted in `PrefLocation.CACHE`) keeps resolved MAL → native ids, skipped items and the fingerprints, so lookups aren't repeated and skips survive a re-fetch. *Review before syncing* (`PrefName.syncConfirm`) shows `SyncController.preview` (updates, adds, lookups, estimated requests) before Sync all; tapping a pair opens a sheet with its differences, the failure reason, Retry and Skip/Include (`SyncOpState.skipped`). Besides any signed-in service the main picker offers *Whichever is ahead* (`syncAheadId`, `SyncAhead.dart`): every service is fetched, entries are grouped by shared ids (one group never takes two entries from the same service), `mergeAhead` picks each group's winner (effective progress — a Completed entry counts as its total —, then status, rewatch count, has-a-score; a missing score is borrowed) and every service, the winner's own included, is planned against the winners, so changes flow both ways; `SyncItem.source` records where a winner came from, and in this mode the instant-sync switch applies to every service. The heavy work runs in isolates (`SyncCompute.dart`: ID expansion, fingerprint, planning/merging via the sendable `SyncTarget` spec that replaces the adapter inside `planWith`; the plan itself is stored as `<Dartotsu>/sync/plan.json`, written and read through `compute`, not in the prefs DB; `SyncController.version` lets the UI memoise its sorted list). **Private entries**: `SyncItem.isPrivate` comes from `Media.isListPrivate`; an adapter with a private option declares `syncsPrivate` (AniList `private`, Kitsu `private`, MangaBaka `is_private`), the pair then carries a `private` diff when the main entry is private and the target's is not, and the writes only ever set it to true (never un-privatise). `PrefName.syncPrivate` (`ask` / `sync` / `skip`, Sync options) decides what happens to private entries because services without a private option would show them publicly: *Sync all* asks first (`askSyncPrivate`, counts the pending private pairs; the answer goes through `SyncController.choosePrivate` so the preview and `isWanted` follow it), instant sync asks per edit, auto sync only includes them with `sync`. Removals are not propagated (no adapter has a throwing delete) and, outside that mode, sync is one-way. UI: `Screen/Settings/Sync/` (`SyncScreen` + `SyncState`; `Components/SyncHeader` = main picker, type, Fetch / Sync all / Stop, progress, collapsible options; `SyncTabs` (`AppTabs`, one per target) + `SyncOverview` (tappable count tiles as filters, rate-limit/pause info, a From/To column header); `SyncPairRow`: main on the left, the target's entry — or a ghost of the main one if it's not in that list yet — on the right).

### Id mapper (`Core/Services/Api/IdMapper.dart`)

One unit for every cross-service id lookup (sync, comments, episode metadata, AniSkip, image search). `IdMapper.index(anime:)` loads the Fribb anime list / the `dartotsu_manga_mapper` manga list **once** (in-flight loads are shared, compacted to `<Dartotsu>/sync/{anime,manga}-ids.json`, refreshed weekly, `IdMapper.warm()` starts both in `_postInit`; `SyncIdIndex` is only the flat table structure). `IdMapper.expand(ids, anime:, prefer:)` fills ids from that table plus everything learned at runtime (`IdMapper.learn` / `learnItems`: every id set a service library, a resolve or a detail load has shown, kept in memory, so a mapping one service knows helps all the others). `IdMapper.resolve(service, media, {need})` returns the full `MetaIds` (anilist, mal, kitsu, simkl, mangabaka, mangaupdates, tvdb, tmdb, imdb) persisted in the title's `MediaRecord.ids`; keys in `need` (and Simkl / MangaBaka on the first run) that are still missing are looked up through the owning service's `SyncAdapter.resolveBy` (one try per title and key per session), and `resolveKey(service, media, key)` is the one-key shortcut. **Services contribute through `SyncAdapter`**: `idsOf` (ids in the data it already holds), `contributeIds(media, MetaIds)` (extra ids such as Simkl's tvdb / tmdb / imdb), `foreignIds` (a request for the ids it knows, Kitsu `/mappings`) and `canResolve` / `resolveKeys` / `resolveBy` (find its own id from another service's id: AniList `idMal_in`, Kitsu `/mappings`, MangaBaka `/source/…`, Simkl's keyless redirect). A new service just implements those; no caller changes.

### Comments, groups and image search

**Comments** (`Screen/Detail/Comments/Data/`, `Screen/Detail/Comments/`) are the Dantotsu comment server (`api.dantotsu.app`) on every title's Comments tab. They are keyed by the *AniList* media id and use the signed-in AniList token (`CommentsApi`: `/authenticate` with the token, session cached in `PrefLocation.CACHE`, re-auth on 401, 6-day lifetime). `CommentsTarget.resolve(service, media)` maps any service's entry to an AniList id through `IdMapper.resolveKey(…, anilist)` (cached per service/media), so MAL, Simkl, Kitsu and MangaBaka pages comment on the same thread; titles that can't be matched show "unavailable", logged-out AniList shows a sign-in card. Profiles open only when the current service is AniList. `CommentsSection` (`ScreenStateHost` + `CommentsState`) holds sort (`PrefName.commentsSort`), episode/chapter tag filter + progress chip, a composer (tag, spoiler `||text||`, Klipy GIF picker, 300 chars, rules dialog on first post), paging on scroll, and `CommentTile` threads: Reddit-style lines (tap to collapse), depth capped at 3 then flattened into the parent list, optimistic votes, level colour from `total_votes`, mod/admin badges, report/delete/ban. `CommentAlerts` polls `/notification/reply` and opens the comment (`openDetail(commentId:)`) from the notification. Toggles: General › Comments.

**Groups** are on `SocialScreenView` (`hasGroups`, `groups`, `group`, `groupPosts`, `groupMembers`, `toggleGroup`, `postToGroup`, `groupScopes`, `hasGroupMembers`; models `SocialGroup`, `GroupPage`): Kitsu implements the real groups API (`/groups`, `/group-members`, `/feeds/group/{id}`, posts with `targetGroup`), MAL maps its read-only forum boards/topics/posts onto the same screens (`members == -1` hides counts). UI: `Screen/Social/GroupsScreen` (reached from the account sheet), `GroupScreen` (Posts | Members | About through the floating nav bar), `Components/GroupCard|GroupMembersTab`; posts reuse `ActivityList(groupId:)` and `ComposerKind.group`.

**Image search**: the search bar has a trace.moe button (anime/movie types): `Core/Services/Api/TraceMoe.dart` + `Screen/Search/Components/ImageSearchSheet`; the picked hit is mapped back to the current service through the Fribb index (falling back to AniList).

**Notifications** (`Screen/Notifications/`): `NotificationsScreen` = service tabs (`AppTabs`, one per signed-in service whose `notificationView` is non-null) + a bottom/side `FloatingBottomNavBar` (service notifications | Comments) + a chip row of `NotificationKind`s from `NotificationScreenView.kinds`. `NotificationFeed` (in `NotificationsState`) holds one service's paged list. The Comments section is the Dantotsu notice list, kept locally in `CommentNoticeStore` (the server delivers a reply once, like Dantotsu's own store). A `NotificationScreenView` also supplies `settings(context)` (shown with every service's rows on `NotificationSettingsScreen`, reached from the tune icon; long-press sends a test notification), `alertsPref` / `pollPref` / `mutedPref` and `unread()` for `Core/Services/ActivityAlerts`, which polls every service with alerts on and shows rich system notifications (cover, title, detail, service as subtitle, tap payload `notif:{json}` opened by `openNotification`). `notificationAlertSettings(view)` builds the shared rows. AniList and Kitsu implement it (the Kitsu feed `/feeds/notifications/{id}` is unverified). Notification log lines carry the `NOTIFICATION` tag. `ProfileScreen` uses the same floating nav bar (Profile | Feed | Stats) instead of tabs. Both alert pollers (`ActivityAlerts`, `CommentAlerts`) start at the top of `_postInit` and poll immediately; `ActivityAlerts` polls every service with alerts on in parallel. `SharedRefresh` (mixin in `ServiceAuth.dart`, on every service auth) shares one in-flight `refreshUser()` per token and logs a failure instead of throwing, so launching offline keeps the cached user and never reaches the crash screen.

### Watch / read tab and episode metadata (`Screen/Detail/Watch/Data/`, `Screen/Detail/Watch/`)

The detail page's Watch/Read tab is `WatchSection` (`ScreenStateHost` + `WatchState`). For every service except Extensions it has a source bar (every installed source of the type through `watchSources(type)` — the Extension page's language filter and drag order apply, its loaded/muted selection does not, last-used source per title, "Wrong title?" search sheet, "Search again"); for the Extension service `media.sourceData` is the fixed source, so there is no selector and the list loads straight from `getDetail(DMedia.withUrl(shareLink))`. `SourceMatcher` searches the source by main name / romaji / synonyms with a Levenshtein + token-sort `titleRatio`, and saves the chosen match per service/source/media (`watchMatch/...`); the *Source matching* setting (closest / exact) decides whether a weak match is accepted. Episodes are renumbered by `normalizeEpisodes` (anime, same rules as `main`), chapters by `prepareChapters` (number from the name when the source gives none); `chunkUnits` splits them into ranges (`watchChunkSizePref`) and `chunkOf` opens the range with the next unit. `UnitTile` has list / grid / compact layouts (watched dimmed from `userProgress`, next highlighted, filler and recap badges, optional spoiler blur), tapping an anime episode loads its streams (`StreamSheet`, or the remembered one when *Auto select stream* is on) and opens the player, tapping a chapter opens the reader (`openReader`); the info icon / `UnitSheet` show the details with Play/Read and mark watched/unwatched (`Mutations.setProgress`, also on long press), the gear beside the source opens `SourceToolsSheet` (source preferences, open the site in the web view to clear Cloudflare, a cookie / `cf_clearance` / user-agent status read from `CookieManager` by `Screen/Detail/Watch/Data/SourceHealth`, a connection test that detects a Cloudflare challenge, clear cookies; the Extension service gets the same bar without the selector), the wrong-title sheet lists results as a `MediaSection`, the Watch tab and the player episode list are slivers (`UnitSliver`, lazy list rows that fade up as they are built; the compact layout is a lazy `SliverGrid`, the card grid stays a non-lazy `UnitLayout`; settings pages build one section per item through `SliverSettingsGroup`), the title row's icon switches the episode-detail provider per title (`MediaWatchSettings.metaSource`: auto / one provider / off), `WatchOptionsSheet` is the per-title media settings (`MediaWatchSettings`: layout, reverse, hidden groups, matching mode, last source — stored under `watchSettings/<service>/<media>`). Global defaults live in Settings › Watch & read (`Categories/WatchSettings.dart`, prefs in `Screen/Detail/Watch/Data/WatchPrefs.dart`), which also holds the Player and Reader settings as sub-screens (`SubSettingsScreen`).

**Episode metadata** is a registry of `EpisodeMetaProvider`s in `Screen/Detail/Watch/Data/Providers/` (ani.zip, Kitsu GraphQL, Simkl `/anime/episodes/{id}`, AniList streaming episodes + airing schedule, Tenrai for filler/recap flags — each checked against the live API on 2026-10-10; Anify (404), Jikan (unreachable, same data as Tenrai) and TMDB (needs a key, covered by ani.zip) were dropped). Extension sources whose seasons restart their numbering (CloudStream) arrive with the season in `scanlator` (`Season N`, `Specials`); `normalizeAll` then groups them, `seasonNames` feeds the season chips and no episode turns into 1.1 / 1.2. The episode list itself always comes from the source: metadata only decorates units by episode number and never adds or removes one, merged field by field in the user's priority order (ani.zip's `episodeNumber` is season-relative, so episodes are keyed by `absoluteEpisodeNumber` and `S*`/`O*` specials are skipped — otherwise One Piece episode 1000 shows 109's data) by `EpisodeMetaService` (enable/disable and drag order in Settings, 30-minute in-memory cache, results stream in as each provider answers). `IdMapper.resolve(service, media)` (the one id mapper, `Core/Services/Api/IdMapper.dart`) turns any service's media into `MetaIds` (see Id mapper below; extension media are matched to AniList by title). Anime only; manga and novels have no metadata providers. AniSkip is not ported (it is player-only).

### Source subscriptions (`Core/SourceAlerts/`)

The bell in the Watch tab's title row (`WatchState.toggleSubscription`, enabled once a source and match exist; extension-service titles use their fixed source and `shareLink`) subscribes a title to release notifications. **One `SourceSub` per service + media** (all in the `sourceSubs` pref, with the capped `SourceNotice` history, owned by `SourceSubscriptions`, `lazyPut`), always on the source the user last picked explicitly: `selectSource(remember: true)` / `chooseMatch` move it once the new source's list has loaded and rebase `lastValue`; the auto-fallback (`remember: false`) never does. A sub keeps everything needed to run `getDetail` without a search (extension manager id + name, source id/name/lang/icon, target url/title/cover, season), a display snapshot (slim `Media`, title, cover, banner, service name) and a metadata snapshot (progress, local progress, list status, total, airing time). **Every manual open refreshes it** through `SourceSubscriptions` (`noteMedia` from `DetailState.load` and `ListEditorState.save`, `noteProgress` from `ResumeStore.noteProgress`, `noteLocal` after a player/reader session, `noteEpisodes` after each episode load): skeleton/offline loads never overwrite, missing values never erase, `lastValue` only goes up (except when the target url or the source changes), progress is taken as-is. `SourceAlerts` (`lazyPut`, `start()` in `_postInit`) runs **one check per app open**, 60 s after launch (it waits while a player is open or a download is running, and does nothing offline or with `sourceAlertsPref` off): every sub's own extension manager is started if it is not running yet (`Extension.initializeInstalled`, also when it is not the current one for the type), then the pure gate `skipReason` runs before any network call (list status Completed, always on; progress 0 while episodes exist; `lastValue` above progress; `nextCheckAt` not reached — the two progress rules have their own switches in Notification settings, "Check now" ignores all of them), at most 6 per launch, 2 at a time, one source at a time with 2 s between calls, 45 s timeout. The extension call stays on the main isolate (the bridge lives there); normalisation, diffing and release-date parsing run in `compute(checkEpisodes)`. `computeNextCheck` (`SourceSchedule.dart`, pure) sets `nextCheckAt` from the median gap of the last 8 release times (`dateUpload` of the loaded units plus the times new ones were seen; gaps under 1 h and over 3x the median dropped, clamped 3 h–30 d): wait `interval - 1 day` (15 % beyond 14 days), an upcoming airing time (AniList's detail `airingAt`) wins, then retry 6 h later, backing off to 12 h / daily / weekly as the release gets late. Failures back off 1 h doubling to 24 h, `unreachable` after 5; a source missing from an active manager's installed list is `missing` (shown with a dash on the Sources page); after 3 failures one re-search (`SourceMatcher.search`, >= 90 %) can repair a moved url. A broken source never removes the subscription; only the bell or Unsubscribe does. New units become one notification per title (several -> "Episodes 12–14", more than 4 titles -> one summary), payload `sub:<service>/<media>` opens the detail page on the Watch tab with that source as the title's default and its match saved (`SourceAlerts.openSub`). `reachedTotal` (service total known and the source has it) refuses a new subscription and ends an existing one (`finished`, still listed). Two services subscribed to the same source url are checked and notified once (`SourceSub.dedupe`). The Extension service's calendar (`ExtensionCalendarView`, the calendar button on its feed tabs) lists the subscriptions' releases of the last day and the expected next ones (`subReleases`: a published airing time, else the last release plus the median gap; marked *Expected*), tapping a row opens the title on that source (`SourceAlerts.openSub`). UI: `Screen/Notifications/` — a third nav item *Sources* that is history only (the `SourceNotice` list), `SourceSubTile` (the dash for a missing source is here), `SourceSubsSheet` (anime / manga / novel chips plus chips per extension service, inactive ones dimmed — the only place subscriptions are listed) opened from Notification settings, which also has the global switch, the two skip switches and *Check now*; the account sheet's bell also shows when the user has subscriptions.

### Per-media state — `MediaRecord` (`Screen/Detail/Watch/Data/Media/MediaRecord.dart`)

Everything the app remembers about one title lives in **one JSON document under one key** (`media/<service>/<media id>`, `MediaRecords.of(service, media)` returns the shared in-memory instance, `MediaRecords.save` writes it, `reset` drops it): the Watch tab's `MediaWatchSettings` (layout, reverse, hidden groups, matching mode, metadata provider, last source), the matched title per source (`matches[sourceId]`), per-episode `playback` positions, `StreamPrefs` (auto select + the last stream label per source), the resolved `MetaIds` (`ids`), the AniList id the comments use (`commentsId`), the per-title player overrides (`player`, only the keys that differ from the global settings), `saveProgress` and `latestUnit` (the highest episode / chapter number the source returned on the last Watch tab load, written by `WatchState._noteLatest`; `MediaRowFacts` shows it on cards whose service has no total, together with a subscription's `lastValue` and the offline manga index's chapter count, and marks it as estimated so only that number gets the tertiary colour). Add new per-title state as a field here — never a new `watch…/<service>/<media>` key. (Local files that have no media keep their position in the single `localPlayback` key, `Screen/Player/Engine/LocalPlayback.dart`.)

### Player (`Screen/Player/Engine/`, `Screen/Player/`)

`PlayerScreen` (+ `PlayerState`) is the Dartotsu player on `media_kit`, with the AnymeX extras. `PlayRequest` = a list of `PlayItem`s (an episode with its `DEpisode`, or a fixed stream for local / network / torrent items) plus optional already-loaded streams; tracked requests carry `service` + `media` + `source` so progress, auto select and per-title settings work, direct ones (`PlayerLauncher.dart`: `playPaths`, `pickAndPlayFiles/Folder`, `askNetworkStream`, `askTorrent`, `playTorrent`) do not. `installPlayerLinks()` (in `_postInit`) points `DeepLink.playFiles` at it, so files opened with the app play. `PlayerEngine` wraps `Player` + `VideoController` with `Live` state (position, tracks, chapters, errors, …), applies the decoder, then the tuning overrides, then `mpv.conf`, then the scripts and shaders; magnet / `.torrent` sources go through the `TorrServerAddon` (`TorrentStream.dart`). `PlayerState` loads a stream list for the item (`source.methods.getVideoList`, preloaded for the next episode at 80 %), picks one (auto select by `bestStreamIndex` against the remembered label, otherwise the stream sheet), resumes from `playback`, saves progress every 5 s, marks the episode watched at 80 % through `Mutations.setProgress` (not in incognito, not when the title's *save progress* is off), auto-plays the next episode, and skips openings / endings / recaps from the stream's own timestamps or AniSkip (`AniSkip.dart`, MAL id; auto skip is optional and once per kind by default). UI: gestures (tap, double tap seek / pause, hold to speed up, brightness / volume swipes on mobile), keyboard shortcuts on desktop (space/K, arrows, shift+arrows frame step, F, N/P, S, M, 0–9, Enter = episode panel), sheets for speed / streams / subtitles / audio / chapters / shaders / options (`Components/PlayerSheets.dart`), and a lock. Options are `PlayerSettings` (a typed view over one map; global in the `playerSettings` key via `PlayerPrefs`, per-title overrides in the `MediaRecord`) and one data-driven row list (`Screen/Settings/Categories/PlayerSettings.dart`: `playerSettingsRows`) serves both Settings › Player and the in-player options sheet. mpv extras live in `<Dartotsu>/mpv/` (`MpvFiles.dart`): `mpv.conf` (editor sheet, parsed by `parseMpvConf`), `Shaders/` (Anime4K v4.0.1 is downloaded on demand from its GitHub release; your own `.glsl` / `.hook` files can be imported and chained, profile `CUSTOM`) and `scripts/` (Lua / JS / native plugins loaded with `load-script`, each switchable; they need a libmpv build with that support). `PlayerScreen` is YouTube-shaped: a 16:9 stage on top with compact controls (back, transport, seek bar, fullscreen), and below it the title, a *Show comments* button and the episode list — `PlayerEpisodes`, the detail page's own `UnitTile` / `RangeBar` / `UnitLayout` in the title's saved view (list / grid / compact), with plain `EpisodeTile`s for items without a `WatchUnit`. *Show comments* slides a layer up over the episode area (an `AnimatedSwitcher`) holding the inline `CommentsSection` filtered to the playing episode through its `episode` Live, with a cross to close it; streams are an icon in the stage's top bar, and the player settings (speed, subtitles, audio, shaders, chapters, resize, options) are a chip row under the title so the compact stage stays clean. The fullscreen button (`PlayerState.enterFullscreen` / `exitFullscreen`) rotates to landscape + immersive on Android / iOS (and `followOrientation` enters it when the phone is turned) and uses window fullscreen on desktop; only the fullscreen layout has the full toolbar (speed, streams, subtitles, audio, shaders, chapters, lock, episode side panel). The same `KeyedSubtree(GlobalKey)` stage moves between the two layouts so playback never restarts. The next episode's stream list is fetched once playback passes 60 % (or 3 minutes remain) and reused by `loadItem`. The system media notification / lock-screen controls are `PlayerMediaSession` (`flutter_media_session`, as on `main`; Android, iOS, macOS and Windows). On Linux the same class starts `PlayerMpris` (`Engine/Mpris.dart`: an MPRIS `org.mpris.MediaPlayer2` D-Bus service over the `dbus` package — `MprisService` owns the bus name `org.mpris.MediaPlayer2.dartotsu`, `MprisHost` is what a player must answer, `PlayerMpris` binds it to the engine), so the media keys, `playerctl`, KDE/GNOME media widgets and the lock screen see title, artwork, position and control play / pause / seek / next / previous / rate. When an episode ends and *auto play* is on, `PlayerNextCard` counts down `PlayerSettings.autoPlayDelay` seconds (Cancel / Play now; 0 = immediate). A long press on the skip button remembers *auto skip* of that kind for the title (`MediaRecord.skips`, read by `_wantsSkip`). *Disable skips* (`PlayerSettings.disableSkips`) stops fetching AniSkip / IntroDB / stream timestamps, hides chapter marks and the skip-submit action and the auto-skip rows. Streams from a source that reports a hoster (`Video.hoster`, Aniyomi's `getHosterList`, carried in the Kotlin `Video.memo`) are grouped by hoster in the stream sheet (`GroupedStreams`), other sources keep the Sub / Dub / Other grouping. `subtitleLanguage` and `audioLanguage` are comma-separated priority lists applied by `TrackPick.dart` (`pickTrack`: stream subtitles first, then embedded tracks, signs/forced avoided; each entry becomes a `LanguageMatcher` through `languageMatcher` — one table maps ISO codes, English names and native names (`es`, `spa`, `Español`, `latino` are the same language), the two-letter code is only tested against the track's language field and never inside a title, so `[HI]` is not Hindi, while names and three-letter codes are matched as whole words in the language and the title; an entry written as `/pattern/` or containing regex characters such as `ja|jpn` is used as the pattern itself; embedded subtitle tracks are waited for up to 15 s in the background (`_pickEmbeddedSubtitle`) because network streams list them late, and a stream subtitle that was loaded is not listed twice in the track sheet, so the selected one is highlighted). The ✨ button in the episode header loads episode metadata inside the player (`PlayerState.loadMeta`, also run for Resume-shelf launches). Brightness on Linux goes through `screen_brightness_linux`, added in the fork `github.com/aayush2622/screen_brightness` (branch `linux-support`, a git dependency in `pubspec.yaml`; upstream is `aaassseee/screen_brightness`, clone `../screen_brightness` has remotes `upstream` (theirs) and `origin` (the fork), sync it by merging upstream `develop` into `linux-support`): systemd-logind `SetBrightness` over D-Bus with a sysfs fallback; `supportsBrightness` is true there only when a backlight device exists. Picture in picture is Android-only and native, with no plugin (`fl_pip` was removed: on iOS it only played a bundled placeholder clip, not the video): `Screen/Player/Engine/Pip.dart` (`PlayerPip`, channel `dartotsu/pip`) and `PipConfig.dart` talk to `android/.../pip/` — `PipController` (enter / exit, `onUserLeaveHint` entry before Android 12, `setAutoEnterEnabled` from Android 12, PiP mode changes, a close of the window reported as `dismissed` so playback pauses), `PipParams` (aspect ratio clamped to 1:2.38–2.38:1, `setSourceRectHint` from the video stage's rect, applied only when the config changed), `PipActions` (remote actions previous / rewind, play-pause, next / forward with localised labels, a dynamic `BroadcastReceiver` registered only while in PiP), `PipModels`, `PipChannel`; icons are `res/drawable/ic_pip_*.xml`. `PlayerState.syncPip()` pushes the config on playing / stream / stage-size changes. The other Android channels live in `android/.../channels/` (one file each) and `MainActivity` only wires them. iOS has no picture in picture: it needs frames from media_kit's `TextureHW` (an `AVSampleBufferDisplayLayer` fed from its pixel buffers), which means patching the media_kit fork. There is no desktop picture in picture. `PlayerScreen._pip` shows only the video while PiP is active. Not ported from Dartotsu / AnymeX yet: external-player hand-off, player themes.

**Casting** (`Core/Cast/`, `Screen/Player/Components/CastSheet.dart`; ported from AnymeX's `lib/services/cast`, without `dlna_dart` / `http`): `CastService` (`lazyPut`, an `AppController` with `Live` state) discovers devices (`CastDiscovery`: mDNS `_googlecast._tcp` for Chromecast, SSDP for UPnP MediaRenderers and Roku ECP), then `cast(...)` starts `CastProxy` (a local `HttpServer` that serves the stream, local files and subtitles to the TV, sniffs the stream first (`CastProxy.isHls` / `contentType`: a `.m3u8` url, an `mpegurl` type or `#EXTM3U` in the first bytes — extension urls often have no extension — else the real `video/*` type, which is what the Chromecast `LOAD` and the DLNA/Roku calls send), rewrites HLS manifests (master or bare media playlists, audio renditions, keys, init maps; segments served as `video/mp2t` / `video/mp4` when the host labels them as images) and adds the request headers the extension asked for, subtitles converted to WebVTT) and loads the proxy URL on the device: Chromecast through `CastV2Client` (hand-rolled CASTV2 over TLS, default media receiver `CC1AD845`, heartbeat, 1 s `GET_STATUS` poll; `LOAD` waits for the receiver's `transportId` (`awaitTransport`, 20 s) instead of a fixed delay, and an `IDLE` / `ERROR` status is shown as a failure), DLNA through `DlnaClient` (SOAP `AVTransport`: `SetAVTransportURI` with DIDL metadata, `Play`/`Pause`/`Seek`/`Stop`, `GetPositionInfo` poll), Roku through ECP `launch/15985` (play/pause key only, no position). `PlayerState.castTo` pauses the local engine and sends `engine.previewTarget` + headers + the matching external subtitle at the current position; `stopCasting` resumes locally where the TV stopped; while casting, progress saving and the watched mark follow the cast position (`_watchPosition`). Leaving the player stops casting. The proxy's address is the local address of a TCP connection to the device (`localAddressToward`), so docker / VPN interfaces are never advertised to the TV (`CastProxy.pickLocalIp` is only the fallback); discovery repeats its mDNS and SSDP queries at 0, 1.2 and 2.6 s; Chromecast only takes the Default Media Receiver's transport (`receiverApp`, another app such as the ambient screen is ignored); DLNA waits for the renderer to leave `TRANSITIONING` / `NO_MEDIA_PRESENT` before `Play` (`playWhenReady`) and sends DLNA.ORG flags for plain files. The cast button is in the chip row. **While casting** the TV is the player: `PlayerState.togglePlayback` / `seekTo` / `seekBy` / `isPlaying` / `duration` / `shownPosition` route to `CastService` instead of the (paused) local engine, so the stage controls, skip button, auto skip, double tap seek, keyboard and progress saving all follow the TV; `selectStream` (next / previous / episode list / quality) opens the new stream locally *paused* (`PlayerEngine.open(autoplay: false)`, still needed for chapters and `previewTarget`) and `_sendToCast` re-casts it at the same position; `CastService.ended` (Chromecast `IDLE`+`FINISHED`, DLNA `STOPPED` at the end) feeds `_onCompleted`, so auto play of the next episode works; sheets no longer resume the local engine (`whilePaused`, window blur are skipped while casting). `CastSheet` (tabs: Controls / Episodes / Chapters) has seek, previous / next, ±seek step, skip intro, TV volume + mute (Chromecast receiver `SET_VOLUME`, DLNA `RenderingControl`), playback speed (Chromecast `SET_PLAYBACK_RATE`), quality chips and subtitle chips: every external subtitle of the stream is served by the proxy (`/subtitles/N.vtt`, `CastSubtitle`) and switched with `EDIT_TRACKS_INFO` (`CastService.setTrack`); DLNA gets only the preferred one. iOS needs the local network usage text (added in `Info.plist`), macOS release needs `network.server`.

### Watch Together (`Screen/Together/`)

A Syncplay client (`SyncplayClient`, `TogetherBackend`; server and backend in `TogetherPrefs`) behind `TogetherController` (`lazyPut`, `attach` / `detach` from `PlayerState`). The host starts a room from the player's *Together* chip (`startHosting`, the invite link is copied) or a guest joins with `dartotsu://together?room=&server=` / the Watch & read settings sheet; **the chip only appears once the player has a shareable remote stream** (`canShare`: an http(s) / magnet url that is not a local address, loaded, within the 7000-character `TogetherStream` payload) or a room is already active. The host shares its stream (`TogetherStream`, gzip + base64 `S:` payload, headers and subtitles included; the id must equal `idOf(url)` and only the host's `S:` / `X:close` are accepted), guests open it through `openTogetherStream` (`TogetherOpener`) and the controller keeps them in step (`_syncGuest`: pause / resume / seek follow, a small rate slowdown when ahead, `R:` asks the host to pause or resume). The room view (`TogetherRoomView`) has members, now playing, chat (`TogetherChat`), *Copy invite* and *Share invite* (`share_plus`, `shareText`).

### Reader (`Screen/Reader/Engine/`, `Screen/Reader/`)

`openReader(ReaderRequest)` (`ReaderLauncher.dart`) opens `NovelScreen` for `format == 'novel'`; for manga / manhwa / manhua it first shows `ReaderLoadSheet` (a bottom sheet that runs `getPageList`, with retry on failure, like `main`) and then `ReaderScreen` with the pages handed over through `ReaderRequest.withPages`. Page images load through `ReaderImageLoader` (3 parallel, retries, in-memory LRU, the real failure reason shown on the page). `ReaderRequest` = service, media, source and the watch tab's `WatchUnit`s. **Manga**: `ReaderState` keeps `segments` (one `ReaderSegment` of `PageUrl`s per loaded chapter, appended forward as you near the end — `settings.preload` items ahead, or on the gap tile's button) and flattens them with `buildReaderItems` into `ReaderPage` / `ReaderSpread` (double pages in landscape) / `ReaderGap` (previous / next chapter tiles) items, so paged and scrolling modes share one model and a chapter change needs no jump. Modes (`ReaderSettings.mode`): `auto` (resolved per title by `autoReaderMode` from the media's format / country into `ReaderSettings.autoMode`, which `scrolls` / `reversed` / `vertical` read through `effectiveMode`: manhwa, manhua and Korean / Chinese titles open as `webtoon`, everything else `rtl`), `rtl`, `ltr`, `vertical` (a `PageView`, `ReaderPagedView`, with per-page pinch / double-tap zoom in `ReaderZoom` that locks the page swipe while zoomed) and `webtoon`, `continuous` (`ReaderWebtoonView`, a `ListView` that finds the centred item through per-item `GlobalKey`s and jumps by estimate + `Scrollable.ensureVisible`). Tap zones are the pure `tapActionFor` (default / L-shaped / Kindle-like / edges / off, RTL and invert aware); scale (fit / width / height / original / smart), background, colour filter, dim, page gap and side padding, page number, fullscreen, keep awake, orientation, preload count and auto next chapter are `ReaderSettings`. Progress: page index per chapter in `MediaRecord.playback` (debounced), the chapter is marked read through `Mutations.setProgress` when its last page or end gap is reached (not incognito, not when *save progress* is off). **Novel**: `NovelState` loads `getNovelContent`, `parseNovel` (`NovelText.dart`, pure) turns the HTML into paragraphs / headings / pictures / rules, `NovelScreen` renders them selectable with font, size, line height, paragraph spacing, margins, justify, bold and a theme (app / light / sepia / dark / black); the scroll fraction (×10000) is the saved position and ≥ 90 % marks the chapter read. Settings are `ReaderSettings` (typed view over one map, global under `readerSettings` via `ReaderPrefs`, per-title overrides in `MediaRecord.reader`), `mangaReaderRows` / `novelReaderRows` (`Screen/Settings/Categories/ReaderSettings.dart`) feed both Settings › Reader and the in-reader sheet; the row helpers (`choiceSetting`, `switchSetting`, `sliderSetting`, `colorSetting`) are shared in `Screen/Settings/Widgets/SettingRows.dart`. Crop borders (`Screen/Reader/Engine/BorderCrop.dart`: a downscaled scan for uniform white/black margins, applied in `ReaderImage` through `ReaderCropScope`), volume-key paging (Android only: `MainActivity` swallows the keys while `VolumeKeys` is enabled) and auto scroll (a timer nudging the webtoon scroll position, or turning pages every few seconds in paged modes; button in the reader's top bar, speed in the settings) are `ReaderSettings`. Two-finger pinch zoom (0.5x–4x) works in every mode, zooming out below 1x is free and letting go springs the page back to normal while zoomed-in pages stay put: `ReaderZoom` (an `InteractiveViewer`) for fit / original pages and `ReaderPinch` (a pointer `Listener` + `Transform`, scrolling and page swiping locked while pinching or zoomed) around the webtoon list and the width / height scaled pages. Bookmarks (`MediaRecord.bookmarks`, a page for manga and a scroll fraction ×10000 for novels; toggle and list buttons in both top bars, `BookmarksSheet`) are per title. Downloaded chapters are read from disk (see Downloads). **Opening a book from the files**: `openLocalBook` (`Screen/Reader/LocalBook.dart`, Settings › Watch & read › *Open a book*, `DeepLink.readFiles` for `.epub` shared or opened with the app, Android `application/epub+zip` filters) builds a one-unit `ReaderRequest(file:)` under a `local/<name>` media with *save progress* off; `NovelState` reads it through `readBookText` (`Core/Downloads/BookText.dart`, epub → one cached HTML in the app cache). PDF is not supported (no renderer in the app). Not built: text-to-speech.

**Novel reader tools** (`Screen/Reader/Engine/NovelLocate|NovelPaginate|NovelSpans.dart`, `Screen/Reader/Components/NovelTools.dart`): the reader's position is a `NovelLocator` (block index + fraction inside the block + the block's first 32 characters; stored beside the old scroll fraction in `Playback.locator` / `Bookmark.locator`, so changing font or margins no longer moves you, and `resolveLocator` re-finds the block by its snippet when the text changed; old saves fall back to the fraction). `NovelState.jumpToBlock` is the one way to go to a block (scroll mode walks the `ListView` with the per-block `GlobalKey`s, paged mode waits for the pages). The *Search and highlights* icon opens `showNovelTools`: **Contents** (`buildToc`: `NovelMark` blocks — `epubToHtml` writes `<div data-toc>` markers from the epub's nav / NCX, cache file `book2.html` — else the chapter's headings), **Search** (`searchBlocks` over the shown blocks, matches painted through `buildSpans`, a floating ‹ n/m › pill steps through them), **Highlights** (`NovelHighlight` in `MediaRecord.highlights`: block + character range + colour + note; the selection menu gets *Highlight* / *Note*, the selection is matched back to the blocks by `locateSelection` because `SelectionArea` only reports plain text; tapping a highlighted word opens `showHighlightSheet`; highlights are hidden while a translation is shown) and **Bookmarks**. *Page turning* (`ReaderSettings.novelPaged`): `paginate` lays the blocks out with `TextPainter` in slices (a paragraph is split at a line boundary, measured height equals the rendered `Text` height) in small time-sliced chunks, `NovelState.pages` fills in while it runs, a `PageView` shows them with tap zones, auto scroll turns pages, and bilingual translation shows only the translation. Read aloud highlights the spoken word where `flutter_tts` reports progress (not Linux's Piper / `spd-say`).

### Dantotsu import (`Core/Preferences/DantotsuImport.dart`)

Settings › Backup › Restore › *Import from Dantotsu* reads a Dantotsu `.ani` (plain JSON) or `.sani` (AES-CBC, PBKDF2-SHA256 10 000 rounds, 16-byte salt first, zero IV; the typed password is padded to 16 characters with `0`, so `2006` is `2006000000000000`). `planDantotsu` turns the file into `DantotsuItem`s (AniList / MAL / Discord tokens, theme, extension repos, update / comment / notification / DNS settings, player speed and subtitle colours) that the user ticks in `DantotsuImportSheet`.

### Resume shelf (`Screen/Detail/Watch/Data/Media/ResumeStore.dart`, `Screen/Home/Components/ResumeShelf.dart`)

AniList Home has an optional *Missing Sequel* rail (off by default, `Queries/GetMissingSequels.dart`): a chunked `MediaListCollection` query (500 entries a chunk, relation nodes are just `id type`, so nothing is downloaded twice for titles already on the list) gives the owned ids and the sequels of *Completed* entries; only the sequels not on the list are then fetched in full with `Page(id_in:)` (50 a page, popularity order, cancelled and, unless AniList's adult setting is on, adult ones dropped, 60 max); the result is cached 24 h under `anilistMissingSequel/<userId>` and refetched only after that or on the user's own pull-to-refresh (`SectionReload.manual`, set by `ScreenWidgetListState.pull`). Home starts with a *Resume* shelf (episode thumbnail, title, `Episode N • mm:ss left` or `Chapter N • Page x of y`, progress bar, a cross to remove). `ResumeStore` keeps one `ResumeEntry` per service + kind + media (newest first, 30 max, one `resume` pref): `PlayerState._saveProgress` and `ReaderState._flushProgress` upsert it for tracked, non-incognito, *save progress* titles once an episode is 10 s in (or a chapter is past page 1) and drop it at 90 %. An entry is hidden (and removed) as soon as the title's list progress is at or above its number: `noteProgress` is called after every `setProgress`, on detail loads and after a player / reader session, and `verify` re-reads the 8 newest titles through `Queries.getMedia` in the background (once per 15 minutes). Only the current service's entries show, and never hidden titles: `MediaService.isHiddenMedia` (list-private or hidden-from-status-lists entries; AniList also its Hidden Media list, Kitsu / MAL / MangaBaka / MangaUpdates adult titles while Hide NSFW is on) stops `record` from adding them and `visible` filters existing ones. The shelf's arrow / title opens `Screen/Feed/ResumeScreen`, a grid of every entry on big cards (`resumeCardStyle`, `resumeItem` are shared with the shelf). Tapping one calls `openResume` (`Screen/Feed/ResumeLauncher.dart`), which opens the player or reader **directly**: the entry stores the raw `DEpisode`, so the source (`installedSourceById`, after `ensureSourcesReady`) can fetch the streams / pages without the detail page. The normal `DetailScreen` is pushed first with no transition so Back lands on it, and it loads in the background untouched (`ResumeStore.endSession` makes it reload when the player / reader closes, so its progress is current). The player starts with a one-item `PlayRequest` (`resume: true` picks the remembered stream without asking) and `PlayRequest.loadItems` fills in the full episode list a moment later (`PlayerState.items` is a `LiveList`); the reader starts with a one-unit `ReaderRequest` (behind the usual loading sheet) and `loadUnits` swaps in the chapter list (`ReaderState._extend` re-bases the open segments). `Screen/Detail/Watch/Data/UnitLoader.dart` (`loadUnits`) is the headless twin of `WatchState._loadEpisodes` (saved source match, `getDetail`, the same renumbering). Entries saved before `episode` existed just open the detail page.

**Android home-screen widget** (`Core/HomeWidget/HomeWidgetSync`, `android/.../DartotsuWidget.kt`, layouts `widget_small|large|row|preview`): one resizable Material 3 widget — a *Continue* card for the newest visible `ResumeStore` entry (cover, `resumeDetail` line, progress bar, play button; tap opens `dartotsu://app/continue`) and, in the larger size, a scrollable list (`ListView` fed by `DartotsuWidgetService`, a `RemoteViewsService` reading the stored payload; rows open through a mutable `PendingIntent` template plus per-row fill-in intents) with up to 9 more `ResumeStore` entries (*Also in progress*, each opens `dartotsu://app/continue?slot=<entry slot>`, which `AppRouteLinks` resolves to that entry and falls back to the newest) followed by the next 6 releases of `ExtensionCalendarView` (tap opens `dartotsu://app/calendar`). Dart builds the whole payload with localised strings (`HomeWidgetSync.push`, debounced 2 s on resume entries / subscriptions / service / locale) and sends it over the `dartotsu/widget` channel; Kotlin stores the JSON in SharedPreferences (so the launcher can redraw without the app), downloads/crops/rounds the covers into `cacheDir/widget` and picks small or large per widget size (`RemoteViews(Map<SizeF, RemoteViews>)` on Android 12+, the widget's min height before). Colours are `widget_*` resources: static brand fallback, `values-v31` maps them to the system dynamic colours (`system_accent1_*` / `system_neutral1_*`, light and night) and the corner radii to `system_app_widget_background_radius` / `inner_radius`. Not built: iOS widgets (needs a WidgetKit target and an App Group, not testable on Linux).

**Local progress** (`Screen/Detail/Watch/Data/LocalProgress.dart`): the per-unit `MediaRecord.playback` positions feed more than the player resume. `effectiveProgress(serviceProgress, units, playback)` is the greater of the service's progress and the highest locally finished (≥ 90 %) unit, and `WatchState.progress` uses it, so the Continue card, the watched dimming, the range chunk and the player's episode list all follow it even when the service hasn't been synced (un-watching a unit clears the local finished marks at or above it). Part-watched units (`partialFraction`) show a progress bar in every `UnitTile` layout, in the detail Watch tab and in the player's episode list (`PlayerState.progressTick`); `ContinueCard` sits on the title's banner / cover and shows the time left or the page of the unit it will open. The reader stores a chapter's last page as `position == count` so a finished chapter counts as finished.

### Downloads and offline (`Core/Downloads/`, `Screen/Downloads/`, `Core/Offline/`)

The transport lives in the bridge (`package:dartotsu_extension_bridge/downloads.dart`: `fetchFile` with resume and chunked ranges, `downloadHls` + the ffmpeg remux, manga page and novel image fetchers, cbz / epub `Archives`, `BookText`, `DownloadPaths`, `DownloadThrottle`; it streams through `BridgeNetwork.downloadClient`, so the app's rhttp stack, cookies and DNS apply). The queue and orchestration are still in `Core/Downloads/` (engine, `DownloadQueue.dart` task building, scanner, snapshots, prefs, foreground service); `Screen/Downloads/` is UI only (picker sheets, page, rows, `DownloadConfirm.dart` = the confirm dialog every delete / cancel goes through, `DownloadStreamSheet` = the stream list with a loading bar, like the online one).

`DownloadEngine` (`AppController`, `lazyPut`, touched in `_postInit`) owns the queue: `DownloadTask`s (kind `video` / `chapter`, state, bytes, chosen stream and subtitle, a `StreamProfile` for batches, a slim media snapshot) persisted in the `downloads` pref, `parallel` slots (`downloadParallelPref`, 1 = one by one), pause / resume / cancel / retry / reorder; an interrupted task comes back `paused`. **Video**: direct files go through `fetchFile` (`FileFetcher.dart`: `.part` file + `Range`, restart if the server ignores it); expired links (401/403/410) re-resolve the stream once, network errors retry with backoff, and when `NetStatus` says there is no connection a task waits (`paused`, "Waiting for a connection") and resumes by itself. **HLS** (the pure parser is the bridge toolkit's `Hls`, `HlsFetcher.dart` downloads): the picker (`chooseHlsMode`) offers to install the bridge's `FfmpegAddon` (mp4 output) or *Keep as folder* (`task.folder`: always the case where ffmpeg is unsupported, e.g. iOS) — a folder download keeps the segments, keys (named `keyN.ts` so mpv's `allowed_extensions` check accepts them) and a local `index.m3u8` in `<Title>/Episode 001/`, and `localVideo` plays that playlist directly (no ffmpeg needed); the chosen variant (`task.height` / `StreamProfile.height`, closest height else the best bandwidth) is downloaded segment by segment (keys and fMP4 init files included, resumable: finished files are skipped) into `.<Episode 001>/`, a local playlist is written and `FfmpegAddon.remuxPlaylist` copies it into `Episode 001.mp4` (`-c copy`, `task.finishing` while it runs); SAMPLE-AES / byte-range playlists are refused. A stream counts as HLS when its url has `.m3u8` / `.mpd` or, failing that, `probeHls` sees an `mpegurl` content type or `#EXTM3U` in its first bytes (`isHlsStream`; AniPM's proxied urls carry no extension, and before the probe they were saved as the playlist text and played back a few seconds); an external audio track whose url is a playlist is merged by `downloadHls(audioUrl:)` instead of being saved as a file. **Torrents**: `TorrServerAddon.addForDownload` + `pickFile(episode:)` + `fileUrl` (bridge, independent of the streaming slot), then the same `fetchFile` over the local url; the torrent is released afterwards. **Manga** (`ChapterFetcher.dart`): `getPageList`, pages saved in their original format (`sniffImageExtension` decides the extension), 3 workers, resumable per page, into `Chapter 012/001.jpg`; **novels**: `getNovelContent` saved as `Chapter 013.html` with its images localised into `Chapter 013_files/`. Files live in `<Dartotsu>/downloads/<service id>/<Title>/` via `DownloadPaths` (a title folder that already exists directly under `downloads/` from before the per-service layout keeps being used; the scanner reads both) (`StorageManager`, Android public Dartotsu folder when permission is granted, `.nomedia` in the root and every title folder) with a `media.json` snapshot (media, episode list, source id — rewritten by `DownloadSnapshots` on every online detail load / unit load, `cover.jpg` refreshed when the cover url changes) and an optional `Episode 001.json` (`downloadInfoFilePref`, off by default; nothing depends on it). `DownloadScanner` (started by the engine, folder watch + pull to refresh) adopts video files dropped into a title folder that has a `media.json` (`episodeNumberOf` in the bridge toolkit's `FileNames` reads `1.mkv`, `E01`, `Ep 12`, `[Group] Show - 05 [1080p]`, `S01E05`, …; any extension in `videoExtensions`, same-named subtitle files attach), lists other folders / loose files as local groups on the Done tab, and drops finished tasks whose files vanished. Picking is `DownloadPicker.dart`: stream sheet, HLS quality sheet, subtitle sheet; the resulting `StreamProfile` (label + subtitle label + height) is applied to the rest of a batch (`_resolve`: fuzzy label match, else the first stream and `fallback = true`); chapters skip the picking. UI: download icon in the Watch tab title row (next / next N / unwatched / range / all), a button in `UnitSheet`, `DownloadBadge` in `UnitTile`, `DownloadsScreen` (Queue / Done / Failed, Done grouped by title, tap plays / reads, title opens the detail page), Settings › Downloads (parallel, notifications, info file, delete watched, offline mode, pending changes). A downloaded unit plays through `localVideo(...)` (`PlayerState.fetchStreams`, `WatchSection._play`) and is read through `localPages` / `localNovel` (`ReaderLoadSheet`, `ReaderState`, `NovelState`; `ReaderRequest.source` is nullable so a downloaded chapter opens without its extension). *Delete watched downloads* (`downloadAutoDeletePref`): `markFinished` at 80 % / last page, `sweepFinished` when the player / reader closes. Notifications: on Android `DownloadService` keeps a `flutter_foreground_task` data-sync service (manifest service + permissions) alive while anything downloads and its notification carries the live progress text (`downloadNotifyPref`: live / done / off; `NotificationManager.showProgress` is the fallback when the service cannot start); elsewhere a completion notification, tap payload `downloads` opens the page (`installDownloadLinks`). **Network rules and speed**: `NetStatus` also tracks the connection kind (`connectivity_plus`: wifi / ethernet / mobile / other / none) and `metered` (Android `dartotsu/network` channel in `MainActivity`, else mobile = metered); `downloadWifiOnlyPref` and `downloadMeteredPref` make `DownloadEngine._syncNetwork` pause active tasks (marked waiting, resumed automatically) and `_pump` hold queued ones, `blockedReason` feeds a banner on the Downloads page; `downloadSpeedLimitPref` (KB/s, 0 = off) is a global pacer (`Throttle.dart`, `DownloadThrottle.take`) used by every `fetchFile` loop (video, HLS segments, manga pages, torrent). **Queue order**: the Queue tab is a `ReorderableListView` with drag handles and a *move to top* button (`reorderQueue` / `moveToTop`, pure helpers `reorderWithin` / `moveBefore` in `DownloadQueue.dart`). **Chapter keys**: a unit's key is its number (`1.0` -> `1`, `1.5` stays `1.5`, so downloads map across sources); only parts of one upload that share a number (same scanlator) get `number~hash`, other scanlators' versions of a chapter share the plain key. **HLS resume**: finished segments are skipped, a partial one continues with `Range`, progress starts at the number already on disk (`downloadHls` takes `getText` / `getFile` hooks for tests). **Archives** (`Archives.dart`): `.cbz` / `.zip` and `.epub` files found in a title folder are adopted as chapter tasks (`DownloadScanner._reading`; `Chapter 12.cbz`, `Vol 3.epub` are numbered by `episodeNumberOf`), a cbz is unpacked once into `.archives/<name>/` (`extractComic`) and read through `localPages`, an epub is flattened to one HTML document with its images extracted (`epubToHtml`, cached as `book.html`) and read through `localNovel`; folders without `media.json` become `local` tasks (service id `local`, progress saving switched off for them). **Torrents**: for a multi-file torrent the picker shows `TorrentFileSheet` (auto-match or choose a file, `task.torrentFile`), and while downloading the row shows seeds / peers from `torrentInfo` (`task.swarm`). **Storage** (`Screen/Downloads/DownloadStorageScreen` + `State`, opened from the "X used by downloads" line): per-title sizes measured in an isolate (`downloadUsage` in `Core/Downloads/DownloadUsage.dart`, pure, tested), a title is "watched" when its `MediaRecord.playback` entry is finished or the snapshot's list progress has reached its number; *Free up space* deletes every watched download after a confirm, each title has *Delete watched* / *Delete all*. Not built: iOS background transfers (downloads run while the app is open), per-title stream profile memory.

**Offline mode** (`Core/Offline/`): `NetStatus` probes DNS every 15 s; `OfflineMode` (`offlineModePref`: auto / off / always) decides at launch only (while it is on, `OfflineGate`, the first rhttp interceptor, fails every request to a non-local host at once with an `RhttpConnectionException('Offline mode')` — loopback, private-range and `.local` hosts such as TorrServer or a LAN server still pass; it covers the extension bridge's clients too) — a connection lost mid-session never flips the mode, it just shows a snackbar (and one when it returns); an *auto* start without a connection ends by itself when it returns. Offline, `DetailState.load` paints the downloaded snapshot (`defaultDetailWidgets`), `WatchState._startOffline` lists the snapshot's episodes (also the fallback when the online load fails), a non-downloaded unit says it is not available offline, and Home and every browse tab switch to `OfflineFeed` (a grid of the service's downloaded titles, opening the snapshot detail page) with an Offline chip that opens the Downloads page; changing the mode shows a snackbar. `MediaService.getMutations` returns `OfflineMutations` for logged-in services: offline (or no connection) an edit / delete / progress is stored by `PendingWrites` (one entry per service + media, coalesced, persisted under `pendingWrites`) and shown through `PendingWrites.overlay` (applied in `DetailState.load`); `replay()` sends them in order through `apiMutations` when the connection returns, offline mode is switched off, or from the Downloads / Settings card; progress writes are dropped if the service is already at or past that value (the "saved offline" notice for automatic progress shows at most every 5 minutes); a Resume-shelf entry whose unit is downloaded opens without its source, so reading / watching history keeps working offline and is replayed when the connection returns.

**Bridge side** (`../DartotsuExtensionBridge`): `FfmpegAddon` (`Engines/Ffmpeg/`, registered in `AddonManager`; a ~4 MB remux-only build (no encoders, filters or network) produced once by `scripts/build_ffmpeg.sh` / the manual `ffmpeg.yml` workflow (artifacts only, no release, so it can't be mistaken for the app's latest release) and committed in the bridge repo's `ffmpeg/` folder; the addon downloads the raw binary from `raw.githubusercontent.com/.../master/ffmpeg/` for Linux / Windows / macOS / Android arm64, no archive; if there is no file for the platform (or the binary will not run) it falls back to the full BtbN / evermeet build; `run`, `remuxPlaylist`, `FfmpegCancel`; unsupported on iOS) and the `TorrServerAddon` download methods (`addForDownload`, `fileUrl`, `torrentInfo`, `pickFile`, `release`).

### Extension tester (`Screen/Extension/ExtensionTest*`; `SourceTester` lives in the bridge toolkit)

The test icon in the Extension page's app bar opens `ExtensionTestScreen`: pick anime / manga / novel, a search term, and *Run* tests the installed sources of that type in the Extension page's own order and language filter (`watchSources`), 10 at a time in parallel (Stop at any time, per-source re-run). `SourceTester.run` walks the same calls the app makes: `search` (needs results with urls), `getDetail` on the first hit, the episode / chapter list (`getDetail().episodes`, entries need urls), then `getVideoList` / `getPageList` / `getNovelContent` for the first entry, and for anime / manga it probes the first link with a ranged GET (HTTP status, TLS, timeout). Each step has a 30 s timeout (60 s for the streams / pages step) and records time, a note and the error with the first stack lines; a failed step skips the ones after it. A failing source opens expanded with the error. The app bar has two copy buttons: the failures report plus the failure-looking log lines captured during the run (`Logger.beginCapture` taps every `logger()` message, including `[Bridge LOGS]`; `failureLogs` keeps errors, `×` requests, 4xx/5xx, timeouts, Cloudflare/FlareSolverr and their stack traces), and the full report with every captured log line.

### Preferences — reactive `Pref<T>` + `PrefManager`

Isar-backed typed KV store with a synchronous in-memory cache, a **shared reactive layer**, and
**microtask-batched writes** (setters never block on disk).

- **`Core/Preferences/Pref.dart`** — `Pref<T>(key, defaultValue, PrefLocation)`. Read/write
  `pref.value`; bind `pref.rx` for a **shared** auto-persisting `Live<T>` (every caller of
  `SomePref.rx` gets the same instance; assigning to it writes through). `enumPref(...)` /
  `jsonPref(...)` for non-primitive `T`. All keys declared once in `Preferences.dart` under
  `PrefName`. `PrefLocation` = `THEME/COMMON/PLAYER/READER/PROTECTED/OTHER` — namespaced into
  the stored key (`THEME/isOled`), so the key alone is the row identity.
- **`Core/Preferences/PrefManager.dart`** — `getVal` / `setVal` / `rxOf` / `removeVal` +
  `getCustomVal` / `setCustomVal` / `getCustomType` / `setCustomType` (all take an optional
  `location:`). `flush()` forces queued writes; a `_schemaVersion` bump triggers a one-time
  wipe (`resetAll()`). Free-function shims kept: `loadData` / `saveData` / `loadCustomData` /
  `saveCustomData` / `removeData` / `removeCustomData`.
- **`Core/Preferences/PrefBackup.dart`** — `export` / `restore` (encrypted via `Encryptor.dart`;
  integrity-checked via `Validator.dart`, which now hashes a canonicalised encoding).
- Single Isar instance `PrefManager.dartotsuPreferences` (schema = `KeyValueSchema` +
  `DartotsuExtensionBridge.isarSchema`), also handed to the bridge.
- The only Isar collection is `KeyValue` (`Core/Preferences/IsarDataClasses/KeyValue/`, committed
  `*.g.dart`); structured values are stored as maps through `setCustomType`.
- **`Core/Preferences/StorageManager.dart`** — `getDirectory({subPath, useCustomPath,
  useSystemPath})` is the single source of truth for on-disk paths (handles Android scoped
  storage / `MANAGE_EXTERNAL_STORAGE`, custom path, Apple sandbox). `String.fixSeparator`
  extension for Windows paths.

### Networking — `NetworkManager`

**`Core/NetworkManager/`**, built on **`rhttp`** (Rust HTTP; `Rhttp.init()` before use). The
`http` package is *not* a dependency. `NetworkManager` (GetxController) exposes `get/post/head/
download` returning `NetworkResponse<T>`, a raw `client` (`RhttpClient`) and
`compatibleClient` (a `package:http` shim for the extension bridge). DoH via `DnsManager`
(Cloudflare default) with `InternetAddress.lookup` fallback; `CookieManager` and `LogInterceptor`
are rhttp interceptors; the in-app browser (`Screen/Webview/WebView.dart`) is `webview_all` (webview_flutter API; WebKitGTK 4.1 on Linux, WebView2 on Windows) — it can't intercept requests, so page traffic no longer goes through `NetworkManager`; cookies are mirrored with `CookieManager.readCookiesFromWebView` / `applyCookiesToWebView` (name/value/domain/path only, per-domain delete = clear all + re-apply the store); `NetworkBridge.dart` / `AppBridgeNetwork` adapt cookies for the bridge.

### Extension system — `dartotsu_extension_bridge`

The saved default manager per type starts at launch and loads its installed list (see the bridge's CLAUDE.md); a manager that is not a default starts only when something needs it (source subscriptions start theirs); `ExtensionState.loadingInstalled` is true while a list loads (the source picker shows a spinner then). Consumed as a **git dependency** on the bridge's `master` (`pubspec.yaml`; a bridge change reaches the app only after it is pushed and `flutter pub upgrade dartotsu_extension_bridge` runs). Unifies
multiple extension backends (Mangayomi, Aniyomi, Sora, CloudStream, Tsundoku, iReader) behind one
interface. `DartotsuExtensionBridge.init(...)` in `main.dart` gets `StorageManager.getDirectory`,
the Isar instance, `client.compatibleClient`, and `AppBridgeNetwork`. Extension-manager UI is
**`lib/Screen/Extension/`** (`ExtensionScreen` ~860 lines, `ExtensionList`). The installed tab shows an *Updates* card above the list (`ExtensionListState.updatable()`, rows with the version change and a per-row update button) with *Update all*, which updates one extension after the other (`updateAll`); updatable sources stay in the normal reorderable list too (the card keeps its update button), so the order never changes because of an update, and `reorder` only moves the visible rows inside the saved order. On Android the bridge throws `ExtensionUpdateConflict` when the system installer closes and the old version is still installed (usually a different signing key); the list then offers *Uninstall and reinstall* (`Extension.reinstallSource`). `add-repo` deep
links are handled in `Utils/Functions/DeepLink.dart` via `find<ExtensionManager>().managers`. Installing or updating an extension manager (`Screen/Extension/Widgets/PluginInstallSheet`, state in `PluginInstallState`) shows the bridge's `InstallStep`s as a checklist: `plugin.plan(refresh: true)` fills it on open (each step waiting / up to date, with size and "will be updated to …"), then it runs — on desktop **Java runtime → runtime core → the manager**, the core taken to its newest version before the manager, each row with its own progress, size and speed ("Step 2 of 3"); a failure marks the step that failed and Try again re-runs only what is left. A manager whose only outdated part is the runtime offers *Update* too. Cancel works until a step is installing. The runtime is also an addon (Settings › Addons › *Java runtime*, removal asks first), and while it downloads at startup the manager's row in the picker says "Preparing the runtime…".

### Discord Rich Presence — `Api/Discord/`

`DiscordPresence` is the immutable activity (`kind` browsing / viewing / reading / watching, type playing / listening / watching / competing, name, details, state, images, timestamps, buttons, `statusDisplay`, plus `vars` — the values `{title}`, `{unit}`, `{number}`, `{total}`, `{progress}`, `{position}`, `{duration}`, `{paused}` that text templates use). `PresenceStyle.fromPrefs()` reads every `discord*` pref and `DiscordPresence.styled(style)` applies them (hide titles, activity type, name mode app / title / custom, status display, templates, large / small image choice, timer style, media / app / custom buttons). ### Deep links

**Service logins** (`Core/Services/Api/BrowserAuth.dart`: `authRedirect(name)` + `browserAuthenticate(url:, redirect:)`) open the user's real browser. On Linux/Windows the redirect is `http://localhost:43721/<service>` (`kAuthPort`) and a one-shot loopback `HttpServer` catches it — custom schemes are unreliable on desktop; an implicit-grant fragment (`#access_token=…`) is forwarded to the query by a tiny page, since fragments never reach a server — then the window is raised. Android/iOS/macOS keep `FlutterWebAuth2`'s native browser session with `dartotsu://<service>`. Services call `authRedirect('anilist' | 'mal' | 'simkl')` and send the result as `redirect_uri` (login and token exchange alike); each service has two API registrations, like Mangayomi's trackers: a mobile client id whose redirect is `dartotsu://<service>` and a desktop client id whose redirect is `http://localhost:43721/<service>`; `authClientId(mobile:, desktop:)` picks by platform (empty desktop id falls back to the mobile one), the per-service constants are `_mobileClientId` / `_desktopClientId` (`malClientId` in `MyAnimeList/Client.dart`).

`Utils/Functions/DeepLink.dart` receives every incoming URI (app_links; Android intent filters, iOS/macOS `CFBundleURLTypes`, Windows registry via `registerProtocolHandler`, Linux `x-scheme-handler` in the installer's `.desktop`) and hands it to the first matching `DeepLinkHandler` in `DeepLink.handlers` (`DeepLinkHandlers.dart`): `ExtensionRepoLinks` (`<scheme>://add-repo`, always asks for confirmation showing the repository url) and `ServiceLinks`. A service claims links by overriding `MediaService.linkHosts` (web hosts, e.g. `anilist.co`), `linkSchemes` (own custom schemes) and, if its URLs aren't `/<kind>/<value>`, `parseUri(Uri)`; `dartotsu://<serviceId>/<kind>/<value>` always reaches that service. `TogetherLinks` (`dartotsu://together?room=&server=`) joins a Watch Together room and `AppRouteLinks` (`dartotsu://app/<continue|search|downloads|calendar>`) opens the app's own screens — the four Android static shortcuts (`res/xml/shortcuts.xml`, long-press the launcher icon) point at the latter. New features add their own handler with `DeepLink.register(...)`; the future player sets `DeepLink.playFiles` (files opened with the app, `dartotsu://play`-style handlers). Register a new scheme in `AndroidManifest.xml`, both `Info.plist`s and `scripts/install.sh`; Windows registers `appSchemes`, bridge schemes and service `linkSchemes` at startup.

## Conventions / gotchas

- **Reuse shared UI** — `CONSISTENCY.md` lists the shared app bar / tabs / empty state / sheet
  components and rules; read it before building any screen chrome.
- **Directory casing**: top-level `lib/` folders are PascalCase (`Core`, `Api`, `Screen`,
  `Model`, `Utils`, `Widgets`). `file_names` / `non_constant_identifier_names` lints are off
  (`analysis_options.yaml`) — match the PascalCase file/identifier style. `camel_case_types`,
  `constant_identifier_names`, `deprecated_member_use`, `library_prefixes` are downgraded to
  `ignore` (the app rides bleeding-edge/forked packages). `prefer_relative_imports: true` and
  `unawaited_futures: true` are enforced — use relative imports within `lib/`.
- Never import `package:get` outside `Core/State` (only `GetBridge.dart` may); no `setState`. Resolve controllers with the `find<T>()` / `put<T>()` helpers. Add
  new long-lived controllers to `DI.init()`.
- Screens: extend `BaseScreen<T>` and implement `buildContent`, don't override `build`. **Every screen is two files**: `FooScreen.dart` (widget + a thin `State` that only builds) and `FooState.dart` (`class FooState extends ScreenState` from `Widgets/Components/ScreenState.dart`: the `Live` fields, controllers, timers, loading/paging/mutation logic and anything derived). The UI `State` mixes in `ScreenStateHost<FooScreen, FooState>`, implements `FooState buildState()` (pass the widget's params in) and reads everything through `state.x`; the mixin calls `onInit` / `onClose` and gives the state `context`, `mounted`, `vsync` (when the UI State has a ticker mixin) and `pop()`. Keep widgets, `Watch` builders and navigation targets in the UI file; keep anything that could be unit-tested in the state. Small leaf widgets (cards, tiles, charts) don't need one.
- Always run `build_runner` after model/Isar changes; commit the regenerated `*.g.dart`.
  There is no `build.yaml`.
- New user-facing strings → `app_en.arb` (+ `flutter gen-l10n`); use `getString.key` (never `const` around it; parameters get ICU placeholders, counts use `plural`). Section titles that double as identifiers (`'Trending Now'`, `'Continue Watching'`, …) stay English in the data layer and are translated at render time by `sectionLabel()` (`Core/Services/SectionTitles.dart`) — add a key + a case there for a new title. Locale files other than `app_en.arb` fall back to English for keys they lack.
- `media_kit` and `media_kit_video` (from `github.com/Predidit/media-kit`, which bundles libmpv through a Dart build hook, so there are no `media_kit_libs_*` packages; `wakelock_plus` is overridden because that fork pins 1.3.3) and `flutter_discord_rpc_fork` are git deps; `flutter_web_auth_2`
  is a personal fork. `dependency_overrides` only pins `collection` and `wakelock_plus`. Treat `pubspec.yaml`
  changes as high-risk.
- Tests: the `test/` folder was deleted; there is no test suite (`flutter_test` is still a dev dependency).

- **`lib/Preferences/`** — same design as the rewrite's `Core/Preferences/` (this is where the
  Isar `*.g.dart` and `PrefName` set are far more complete on `main`).
- **`lib/Theme/`** — `ThemeManager` / `ThemeProvider` / `LanguageSwitcher` / `Themes/`.
- **`lib/Functions/`** — `AppShortcuts`, `RegisterProtocol/`, extension helpers. Rewrite moved
  these under `Utils/`.
- **`lib/Api/Discord/`** — Discord RPC (ported to `lib/Api/Discord/` here too).
- **`lib/logger.dart`** — same logger design (lowercase filename on `main`, `Logger.dart` here).

**Key differences `rewrite-re` vs `main`:**

| | `main` | `rewrite-re` |
